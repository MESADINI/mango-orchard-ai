# Dataset card: Merged pest detection set (FLAGGED proxy data)

Tables marked AUTO are generated by `ml/datasets/make_cards.py` from `results/data/pest_dataset.json`.

> **Status: built, but no source shows pests on mango.** The host-plant review (below) found that each of the three
> public sources shows a different host or setting: trap photos, grape and coffee. The merged set is therefore
> **proxy data**. A detector trained on it may recognise the insect types, but it is not validated on mango trees.
> The app and paper must say so (see "Consequences"). The strict mango-only build
> (`build_pest_dataset.py build` without `--include-non-mango`) currently yields **zero images**.

## Processing (`ml/datasets/build_pest_dataset.py`)

- Download via the Roboflow REST export API (key read from `ROBOFLOW_API_KEY`, never logged). Files are extracted
  with short names because of the Windows path-length limit; `names.csv` maps them back.
- Labels are remapped to `["Fruit Fly", "Mealy Bug", "Scale Insect"]`. Only the named source classes are kept;
  invalid lines are dropped and counted.
- Images whose every box belonged to a dropped class (e.g. only `Grape` or `Pest` boxes) are **removed**: they
  may contain unlabelled target pests and would teach the detector false negatives.
- Exact SHA-256 duplicates are removed. Roboflow augmentation copies (`<stem>_<ext>.rf.<hash>`) and dihedral
  pHash-identical images are grouped. Roboflow's own splits are ignored, and a group-aware, class-stratified
  70/15/15 split is used (seed 42).
- Gated classes (Rule 3: Mango Hopper, Stem Borer) can never enter the set (`build_id_map` raises).

## Consequences for the rest of the project

1. **Per-class host flag.** The detector and its outputs must carry `host_verified: false` for all three classes,
   and the UI must show "trained on non-mango images; confirm by inspection" with any detection. (Wired in
   Phase 3/6.)
2. **OHI.** The pest component of the OHI keeps its existing disclosure logic. Detections from host-unverified
   classes are reported, and the OHI breakdown labels them as such.
3. **Treatments.** The mango-specific protocols (e.g. *Drosicha mangiferae* trunk banding) apply to mango pests.
   A proxy-trained detection is a prompt to inspect, not a diagnosis.
4. **Paper.** Pest results must be described as proxy-domain results, never as mango orchard performance.

## Gated classes (Rule 3)

Mango Hopper and Stem Borer: no source with ≥ 100 verified boxes exists. See
`ml/datasets/pest/MANUAL_ANNOTATION_GUIDE.md` for the annotation and promotion procedure. The same procedure
(collect mango images, have the boxes verified, record the review with `"host": "mango"`) is the way to replace the
proxy sources above.

## Known issues

- Each source holds a single class, so every image contains only one pest type. Background and imaging style
  differ completely per source (grayscale trap vs. colour grape vs. coffee leaf in the hand), so the
  detector can tell classes apart by *context* instead of insect appearance (shortcut risk). Report per-source
  results, and test on mango field images (`ml/datasets/field/pest_images/`) before any claim.
- Fruit-fly instances are much denser per image (many flies per trap photo) than the other classes.
